# Development and tests

Use Python 3.12 and Node.js 24 for the verified development path. Python package metadata permits 3.11–3.13, but CI currently qualifies 3.12. Full GPU inference uses the separate Docker runtime; CPU source development does not install music weights or CUDA.

## Setup

Create and activate a virtual environment at the repository root:

~~~sh
python -m venv .venv
~~~

On Linux/macOS:

~~~sh
source .venv/bin/activate
~~~

On PowerShell:

~~~powershell
.venv\Scripts\Activate.ps1
~~~

Then:

~~~sh
python -m pip install -e ".[test]"
npm ci
npm run build
python -m uvicorn backend.app:app --host 127.0.0.1 --port 8000
~~~

Set DAW_STORAGE to a writable directory before starting; .data is convenient for local work and is ignored by Git. For Linux/macOS use export DAW_STORAGE="$PWD/.data"; in PowerShell use $env:DAW_STORAGE="$PWD/.data". Create the directory if needed. A source install is run from its checkout; the separately built frontend lives in dist.

Run npm run dev in another terminal for Vite and keep the API on port 8000. See vite.config.ts for the development proxy. Changes to Python backend code require restarting the server, or using Uvicorn's --reload option locally.

FFmpeg must be available for audio/video conversion. The Python imageio-ffmpeg dependency supplies a fallback executable; the Docker image installs the system FFmpeg package. CUDA and the official YuE2 wheel are intentionally kept out of CPU installation.

## CPU tests

~~~sh
python -m pytest -q
npm test
npm run build
python -m scripts.changelog --check
python -m scripts.check_source
~~~

Backend tests force unique temporary storage beneath .runtime and clean only their own fixtures. Never point test helpers at production storage.

## Browser tests

~~~sh
npx playwright install chromium
npm run build
npm run test:browser
~~~

Linux uses Playwright Chromium; install OS dependencies with npx playwright install --with-deps chromium where appropriate. Windows defaults to installed Microsoft Edge. Set PLAYWRIGHT_CHANNEL=chromium to use the downloaded Chromium instead.

The suite starts a separate server at 127.0.0.1:8014, uses synthetic audio and test-only API routes and needs no GPU. DAW_TEST_DIST optionally selects another build; the default is dist. Failure traces/screenshots stay in .runtime. Phone viewport tests do not prove physical device background playback.

## Source layout

| Directory | Contents |
| --- | --- |
| src | React workspaces, shared project state, browser audio engine and frontend tests |
| backend | FastAPI, validated schemas, persistence, queue, inference and media processing |
| public | App favicon, AudioWorklet and font license notices |
| scripts | Build, model verification, source-release and isolated browser-test helpers |
| tests | Backend regressions and Playwright browser scenarios |
| docs | User/developer guides and upstream license notices |

src/visual-model.ts is generated by python -m scripts.generate_visual_types. Follow the schema generator's output path when changing the shared visual contract.

## GPU validation

Use Secure Cloud and a disposable persistent test volume. Build the Docker image described in [releasing](RELEASING.md). Changes to inference, model selection, memory residency or audio processing need real GPU/audio validation; CPU mocks alone are insufficient. Existing users' active Radio stations and projects are not test fixtures.

scripts/verify_bundled_models.py and scripts/verify_bundled_voice.py are explicit container checks, not part of routine CPU CI. Read each script before running; a voice check may load GPU models. scripts/check_mcp.py is an opt-in remote client check using CADENTRAIL_URL and CADENTRAIL_TOKEN; its --write option creates temporary work. Keep those values private.
